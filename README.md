## 设计理念

大模型在代码生成与流程设计上的效率已经无需争论。但当处理对象是内部资料、业务台账、汇报材料时，「把文件上传给在线 AI、让 AI 直接给出结果」这条路径存在几个难以回避的问题：

| 关注点 | 直接使用在线 AI 处理 | 使用 AI 生成的本地工具处理 |
| --- | --- | --- |
| 数据流向 | 文件内容离开内网，进入第三方服务 | 全程留在本机 / 内网，不出网 |
| 结果稳定性 | 同一份文件两次处理，结果可能不一致 | 逻辑固定，输入相同则输出相同 |
| 可追溯性 | 难以说明「这份文件被什么规则改过」 | 规则写在代码里，逐行可查、可审计 |
| 断网可用性 | 断网即不可用 | 断网环境照常运行 |
| 使用成本 | 每次处理都消耗模型调用 | 部署一次，长期零成本反复使用 |

因此本项目采用一种更稳妥的分工方式：

> **由 AI 一次性完成工具的设计与编码，之后所有文档处理都在本地或内网环境由这套工具完成。**

AI 负责「造工具」这一高价值环节；敏感数据的处理则交给逻辑确定、离线运行的程序。既保留了 AI 带来的效率提升，又让数据始终在自己的边界内流转。

一句话概括：**AI 帮我们把活做成工具，工具在断网环境里替我们把活干完。**

## 核心特性

- **数据不出网** — 所有解析、转换、合并、脱敏均在本地进程内完成，不调用任何外部接口，运行期无需联网。
- **零外部依赖服务** — 仅依赖 Python 与若干纯本地文档处理库，不需要数据库、中间件或云服务。
- **结果可复现** — 处理规则以代码形式固定，同一输入可稳定得到同一输出，便于复核与留痕。
- **批量处理** — 支持多文件一次上传、结果打包下载，减少重复性手工操作。
- **可裁剪** — 12 项功能均可通过配置开关独立启停，未启用的功能在界面上置灰、接口同步拒绝服务。
- **轻量易部署** — 单机单进程启动；也可打包为单个可执行文件，双击即用，无需安装 Python。

## 功能特性

### 1. Word 文档深度处理

| 功能 | 说明 | 输入 |
| --- | --- | --- |
| 多文档一键合并 | 按上传顺序合并为一份，文档之间自动插入分页符 | 多个 `.docx` |
| 文档脱敏与排版 | 正则脱敏手机号 / 身份证号 / 座机，清除多余空行，全文段落首行缩进 2 字符 | 单个 `.docx` |
| 关键信息提取库 | 批量提取时间、手机号、座机、身份证号、邮箱、金额、疑似地址，汇总为一张 Excel | 多个 `.docx` |

### 2. Excel 台账智能清洗

| 功能 | 说明 | 输入 |
| --- | --- | --- |
| 大表按分类拆分 | 按指定列（如「部门」）的唯一值拆分为多个 Excel，打包 ZIP 下载 | 单个 `.xlsx` |
| 多表横向对齐合并 | 以首个文件为主表，按关键列（如身份证号）横向拼接其他表的所有列 | 多个 `.xlsx` |
| 身份证信息智能解析 | 自动识别身份证列，新增「出生日期」「性别」「年龄」三列并填充 | 单个 `.xlsx` |

### 3. PPT 汇报结构化

| 功能 | 说明 | 输入 |
| --- | --- | --- |
| 汇报大纲一键提取 | 提取每页标题与正文，按层级生成 Word 大纲文档 | 单个 `.pptx` |
| PPT 批量加防伪水印 | 在每页中央添加倾斜文字水印，水印文案可自定义 | 多个 `.pptx` |
| PPT 图片提取打包 | 打包 PPT 中嵌入的全部原始图片 | 多个 `.pptx` |

### 4. PDF 与档案批处理

| 功能 | 说明 | 输入 |
| --- | --- | --- |
| 多 PDF 一键合并 | 按上传顺序合并为一份新 PDF | 多个 `.pdf` |
| 批量文件规范化重命名 | 按「前缀 + 原名 + 后缀」规则批量重命名，支持任意文件类型 | 任意文件 |
| 长文本极速清洗 | 去除乱码、控制字符、多余空行；可按关键词提取句子 | `.txt` 或直接粘贴文本 |

## 快速开始

### 方式一：直接下载可执行文件

从 [Releases](../../releases) 下载对应平台的可执行文件，放到有写入权限的目录后双击运行，浏览器会自动打开工作台。

### 方式二：从源码运行

```bash
git clone https://github.com/TangAIForge/local-document-workbench.git
cd local-document-workbench

# 建议使用虚拟环境
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
python app.py
```

启动后访问 <http://127.0.0.1:5000>，按 `Ctrl+C` 停止服务。

### 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows / macOS / Linux |
| Python | 3.8 及以上（推荐 3.10+） |
| 网络 | **运行期无需联网**（仅首次安装依赖时需要） |
| 内存 | 建议 2 GB 以上；单次上传上限 500 MB |

### 断网环境安装

在可联网的机器上下载依赖离线包：

```bash
pip download -r requirements.txt -d ./wheels
```

将 `wheels/` 与源码一并拷贝到目标机器后安装：

```bash
pip install --no-index --find-links=./wheels -r requirements.txt
```

## 使用说明

### 通用流程

1. 打开工作台首页，页面自动加载后端下发的功能清单与开关状态；
2. 在目标功能卡片中，**点击虚线框或直接把文件拖拽进去**（支持多选的功能会提示「可多选」）；
3. 如该功能有参数项（如「拆分列名」「水印文字」），按需填写，留空则使用默认值；
4. 点击卡片底部的 **开始处理**；
5. 处理完成后卡片下方出现结果条，点击文件名即可下载；
6. 结果文件统一保存在程序目录的 `downloads/` 下。

> 页面右上角显示「本地服务运行中」表示后端连接正常；卡片显示「已关闭」表示该功能被管理员在系统设置中停用。

### 各功能要点

| 功能 | 关键参数 | 说明 |
| --- | --- | --- |
| 多文档一键合并 | — | 严格按上传顺序合并，自动跳过原文档节属性以避免版式错乱 |
| 文档脱敏与排版 | — | 手机号 → `1XX**********`；身份证号 → `******************`；座机 → `0XXX-XXXXXXX`；正文与表格均处理 |
| 关键信息提取库 | — | 同一文档内多个命中值以 ` / ` 分隔，输出已冻结首行 |
| 大表按分类拆分 | 拆分列名（默认 `部门`） | 该列为空的行归入「未分类」；列名不存在时返回错误并列出全部列名 |
| 多表横向对齐合并 | 匹配列名（默认 `身份证号`） | 首个文件为主表，行序不变；新增列命名格式 `原列名(来源文件名)` |
| 身份证信息智能解析 | 身份证列名（留空自动识别） | 先按列名关键词匹配，再扫描前 30 行数据；自动还原科学计数法 |
| 汇报大纲一键提取 | — | 按「第 N 页：标题」分节，表格内容以 ` \| ` 分隔 |
| PPT 批量加防伪水印 | 水印文字（默认 `内部资料 严禁外传`） | 每页中央 −30° 倾斜浅灰文字；多文件自动打包 ZIP |
| PPT 图片提取打包 | — | 直接读取 PPT 包内媒体资源，导出未经压缩的原始图片 |
| 多 PDF 一键合并 | — | 按上传顺序合并 |
| 批量文件规范化重命名 | 统一前缀（默认 `内网文件_`）、统一后缀 | 不修改磁盘原文件，在压缩包内生成重命名副本 |
| 长文本极速清洗 | 直接粘贴文本 / 提取关键词 | 去除控制字符、零宽字符与乱码；有关键词时按句切分并筛选 |

### 功能开关

点击顶部「系统设置」进入开关管理页，支持「全部开启 / 全部关闭」批量操作，修改后点击 **保存设置** 生效。

关闭某项功能后：工作台对应卡片置灰不可点击，后端接口同步返回 403。开关的键名与 `config.json` 字段一一对应。

也可通过地址栏直达：`http://127.0.0.1:5000/#settings`。

## 打包为可执行文件

项目自带打包脚本，基于 [PyInstaller](https://pyinstaller.org/)：

```bash
pip install pyinstaller
python build.py            # 单文件可执行程序
python build.py --clean    # 先清理 build/ dist/ 再构建
python build.py --onedir   # 目录版，启动更快、便于排查问题
```

产物位于 `dist/`。程序运行后会在**自身所在目录**生成 `config.json`、`uploads/`、`downloads/`，不会写入临时目录。

### 可配置的环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WORKBENCH_HOST` | `127.0.0.1` | 监听地址。改为 `0.0.0.0` 可供局域网访问，请自行评估网络可控性 |
| `WORKBENCH_PORT` | `5000` | 起始端口。若被占用会自动向后顺延最多 12 个端口 |
| `WORKBENCH_NO_BROWSER` | 未设置 | 设为 `1` 时启动后不自动打开浏览器（适合服务器部署） |

## 接口一览

所有功能接口均为 `POST`，请求体为 `multipart/form-data`。

| 接口 | 功能 | 主要参数 |
| --- | --- | --- |
| `/api/word/merge` | 多文档合并 | `files`（多个） |
| `/api/word/redact` | 脱敏与排版 | `files`（单个） |
| `/api/word/extract` | 关键信息提取 | `files`（多个） |
| `/api/excel/split` | 大表按分类拆分 | `files`、`column` |
| `/api/excel/merge` | 多表横向合并 | `files`（多个）、`keycol` |
| `/api/excel/idcard` | 身份证解析 | `files`、`idcol` |
| `/api/ppt/outline` | PPT 大纲提取 | `files` |
| `/api/ppt/watermark` | PPT 加水印 | `files`（多个）、`text` |
| `/api/ppt/images` | PPT 图片提取 | `files`（多个） |
| `/api/pdf/merge` | PDF 合并 | `files`（多个） |
| `/api/file/rename` | 批量重命名 | `files`（多个）、`prefix`、`suffix` |
| `/api/text/clean` | 文本清洗 | `text` 或 `files`、`keyword` |

辅助接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/` | GET | 工作台页面 |
| `/api/ping` | GET | 服务健康检查 |
| `/api/config` | GET | 读取功能开关与功能元数据 |
| `/api/config` | POST | 保存功能开关（JSON 请求体） |
| `/api/download/<filename>` | GET | 下载结果文件 |

成功时返回 `status: "ok"`，并携带 `filename` 与 `download_url`；失败时返回 `status: "error"` 与中文 `message`。

## 常见问题

**Q：启动后浏览器打不开页面？**
先访问 `http://127.0.0.1:5000/api/ping`，返回 JSON 说明服务正常，问题可能出在浏览器代理设置；若无响应，检查终端是否报错、端口是否被占用（Windows：`netstat -ano | findstr :5000`）。

**Q：提示「该功能已被管理员关闭」？**
该功能在系统设置中被停用。进入「系统设置」重新开启并保存，或直接编辑 `config.json` 将对应键改为 `true` 后重启。

**Q：提示「未找到列 [XXX]」？**
Excel 拆分与合并要求列名与表头**完全一致**（含空格与标点）。错误信息会列出当前表的全部列名，据此核对即可。

**Q：处理大文件很慢或超时？**
单次上传上限 500 MB。超大 Excel 建议先按行数拆分；合并类操作会占用相应内存，建议在配置较高的机器上执行。

**Q：结果文件会一直留在 `downloads/` 吗？**
会。上传的临时文件在处理结束后自动清理，但结果文件会保留，需要定期手工清理或纳入例行维护。

**Q：脱敏结果能直接对外发布吗？**
不能完全依赖。脱敏基于正则规则，覆盖面有限。若文档中存在非标准格式的敏感信息（带空格的号码、非常规编号等），建议处理后再人工抽查。

**Q：可以在断网环境部署吗？**
可以。按上文「断网环境安装」准备依赖离线包后，整套工具在无网络环境下可正常安装与运行，运行期不发起任何外部请求。

## 安全说明

- 全部处理逻辑在本地进程内完成，**不上传、不回传任何文件内容**；
- 默认仅监听 `127.0.0.1`，即只有本机可访问。如需局域网共享，请先评估所处网络的可控性；
- 服务未内置账号体系。若部署在内网服务器供多人使用，建议置于内网网关之后，或自行增加访问控制；
- 脱敏与信息提取均基于正则规则实现，属于「辅助降低暴露面」的手段，**不能替代正式的数据安全审查流程**；
- 请在使用前确认所处理文档的授权范围，并按所在单位的资料管理规定处置结果文件。
